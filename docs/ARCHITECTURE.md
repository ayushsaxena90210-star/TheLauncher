# Architecture

## System boundary

The Launcher is a local desktop application. Internet use is limited to user-initiated metadata and artwork retrieval. It has no server-side account, synchronization, telemetry, or social system.

```text
┌─────────────────────────────────────────────────────────┐
│ Electron                                                  │
│  Main: windows, dialogs, launching, notifications, IPC   │
│  Preload: minimal typed, allow-listed bridge              │
└───────────────┬──────────────────────────┬──────────────┘
                │ IPC                      │ localhost HTTP
┌───────────────▼──────────────┐  ┌─────────▼──────────────┐
│ React renderer               │  │ FastAPI                 │
│ routes, components, state,   │  │ validation, use cases,  │
│ forms, loading/error states  │  │ scanning, search, stats │
└──────────────────────────────┘  └───────┬─────────┬──────┘
                                           │         │
                                    ┌──────▼───┐ ┌──▼──────────┐
                                    │ SQLite   │ │ Asset cache │
                                    └──────────┘ └─────────────┘
```

## Responsibilities

| Layer | Owns | Must not own |
| --- | --- | --- |
| React | UI composition, route state, accessibility, form presentation | scanning, persistence, launch policy |
| Electron main | windows, native dialogs, safe executable spawning, notifications, IPC validation | database access and library business rules |
| FastAPI | game/library use cases, SQLite, scanning, metadata/artwork orchestration, search and statistics | renderer state or visual components |

## Hydration from the Hydra reference

Hydra demonstrates a useful Electron split: a main process, a tightly scoped preload bridge, and a React renderer. The Launcher will adopt that separation, component-oriented UI, and game-library navigation patterns. It will not copy Hydra code or implement its download, torrent, account, cloud, friends, achievement, telemetry, or update-service features.

## Module direction

Dependencies must point inward: routes/components depend on UI services; UI services depend on typed client contracts; FastAPI route handlers depend on application use cases; use cases depend on repository interfaces; repositories implement SQLite/filesystem details.

## Security and reliability baseline

- Keep `contextIsolation` enabled and disable unrestricted Node access in renderers.
- Expose only named preload methods; validate IPC payloads in Electron.
- Validate all paths and executable launches. Never use a shell string to launch a game.
- Treat remote metadata and images as untrusted; use timeouts, size limits, content-type checks, and local cache paths generated by the app.
- Log errors locally with actionable context, without collecting telemetry.
